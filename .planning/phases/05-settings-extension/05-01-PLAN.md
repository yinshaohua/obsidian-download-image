**Step 4 — Rewrite `display()` method with sections, dropdown, warning, and textarea:**

The full `display()` method body:

```typescript
display(): void {
  const {containerEl} = this;
  containerEl.empty();

  // ── Download section (D-08, D-09) ──
  containerEl.createEl('h2', { text: 'Download' });

  new Setting(containerEl)
    .setName('Image naming strategy')
    .setDesc(
      'How downloaded images are named. URL hash derives a deterministic name from the image URL; ' +
      'Timestamp adds a date prefix; Content hash uses file content for deduplication.'
    )
    .addDropdown(dropdown => dropdown
      .addOptions({
        original: 'URL hash',
        timestamp: 'Timestamp prefix',
        hash: 'Content hash',
      })
      .setValue(this.plugin.settings.namingStrategy)
      .onChange(async (value) => {
        this.plugin.settings.namingStrategy = value as NamingStrategy;
        await this.plugin.saveSettings();
      }));

  new Setting(containerEl)
    .setName('Concurrent downloads')
    .setDesc('Maximum number of simultaneous image downloads (1-10).')
    .addSlider(slider => slider
      .setLimits(1, 10, 1)
      .setValue(this.plugin.settings.concurrency)
      .setDynamicTooltip()
      .onChange(async (value) => {
        this.plugin.settings.concurrency = value;
        await this.plugin.saveSettings();
      }));

  // ── Cleanup section (D-08, D-09) ──
  containerEl.createEl('h2', { text: 'Cleanup' });

  // Cleanup method dropdown (D-01)
  new Setting(containerEl)
    .setName('Cleanup method')
    .setDesc('How orphaned attachments are removed.')
    .addDropdown(dropdown => dropdown
      .addOptions({
        trash: 'Move to .trash',
        delete: 'Permanent delete',
      })
      .setValue(this.plugin.settings.cleanupMethod)
      .onChange(async (value) => {
        this.plugin.settings.cleanupMethod = value as CleanupMethod;
        await this.plugin.saveSettings();
        warningEl.style.display = value === 'delete' ? 'block' : 'none';
      }));

  // Inline warning for permanent delete (D-02, D-04)
  const warningEl = containerEl.createEl('p', {
    text: 'Warning: Files will be permanently deleted and cannot be recovered.',
    cls: 'mod-warning',
  });
  warningEl.style.display =
    this.plugin.settings.cleanupMethod === 'delete' ? 'block' : 'none';

  // Folder exclusions textarea (D-05, D-06, D-07)
  new Setting(containerEl)
    .setName('Excluded folders')
    .setDesc('Folder paths to exclude from orphan scan (one per line). Uses exact prefix matching.')
    .addTextArea(textarea => textarea
      .setPlaceholder('attachments/archive\ntemp')
      .setValue(this.plugin.settings.excludedFolders.join('\n'))
      .onChange(async (value) => {
        this.plugin.settings.excludedFolders = value
          .split('\n')
          .map(s => s.trim())
          .filter(s => s.length > 0);
        await this.plugin.saveSettings();
      }));
}
```

Key details:
- `warningEl` is a LOCAL variable inside `display()` — avoids stale DOM reference on re-render (Research pitfall 1)
- `warningEl.style.display` toggled in `onChange` AND set on initial render based on current value
- Textarea `onChange` parses: `split('\n') -> map(trim) -> filter(nonEmpty)` per D-05
- `cls: 'mod-warning'` for visual warning style (Claude's discretion per D-04 notes)

Malformed paths (e.g., `../../secret`) simply won't match any vault-relative path. Phase 7 deletion uses TFile objects, not exclusion strings. |

| T-05-03 | Denial of Service | Large exclusion list | accept | Textarea input has no hard limit, but exclusion list is iterated once per file in collectOrphans(). For vaults with thousands of files and dozens of exclusions, performance impact is negligible (O(files * exclusions) with short-circuit). |
