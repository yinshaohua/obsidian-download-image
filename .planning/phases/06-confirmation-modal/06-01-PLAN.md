           .filter(([, cb]) => cb.checked)
           .map(([path]) => this.orphans.find(o => o.file.path === path)!.file);

`onClose()` method (safety net — D-09, Pitfall 1):
```typescript
onClose(): void {
  if (!this.resolved) {
    this.resolved = true;
    this.resolveFn(null);
  }
  this.contentEl.empty();
}
```

**`showCleanupModal` async helper function** (exported — D-08):
```typescript
export async function showCleanupModal(
  app: App,
  orphans: OrphanedFile[]
): Promise<TFile[] | null> {
  if (orphans.length === 0) {
    new Notice('No orphaned attachments found');
    return null;
  }
  return new Promise(resolve => {
    new CleanupModal(app, orphans, resolve).open();
  });
}
```

Per D-07: empty orphans array triggers Notice, never opens modal.
Per D-08: signature is `showCleanupModal(app: App, orphans: OrphanedFile[]): Promise<TFile[] | null>`.
Per D-09: Confirm returns selected TFile[], Cancel/dismiss returns null.
Per D-10: Phase 7 will `await showCleanupModal(...)`.
Per D-11: No Notice from the modal on Confirm — Phase 7 handles the result Notice (CLN-04).

**CRITICAL ordering in button handlers:** Set `this.resolved = true` THEN call `this.resolveFn(value)` THEN call `this.close()`. This prevents the double-resolution race (Pitfall 2).
