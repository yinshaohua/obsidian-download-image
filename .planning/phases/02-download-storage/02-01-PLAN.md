**3. Pure helper functions (no Obsidian API, no side effects):**

`isValidImageContentType(contentType: string | undefined): boolean` — per D-08:
- Return `false` if `contentType` is undefined or empty
- Lowercase the value, return `true` if it starts with `'image/'` OR equals `'application/octet-stream'`
- Return `false` otherwise

`deriveFilenameFromUrl(url: string, contentType?: string): string` — per D-01, D-02:
- Strip query (`?`) and fragment (`#`) from URL
- Extract last path segment via `.split('/').pop()`
- If segment has a file extension matching `/\.\w{2,5}$/`, return the segment directly
- If no valid extension: infer extension from contentType via `MIME_TO_EXT` lookup (split on `;` first, trim, lowercase), default to `'png'`
- If segment is empty or shorter than 3 chars (CDN hash/UUID), use `image-${Date.now()}` as base name
- Return `${base}.${ext}`

`deriveFilenameFromBase64(mimeType: string): string` — per D-03:
- Look up extension in `MIME_TO_EXT` from mimeType (lowercase), default to `'png'`
- Return `base64-${Date.now()}.${ext}`

`decodeBase64Image(dataUri: string): { buffer: ArrayBuffer; mimeType: string }` — per D-13, D-14:
- Split on first comma: `const [header, base64Data] = dataUri.split(',');`
- Validate both parts exist, throw `Error('Invalid data URI format')` if not
- Extract MIME type: `header.replace('data:', '').replace(';base64', '')`
- Decode: `const binaryString = atob(base64Data);`
- Convert to ArrayBuffer: create `Uint8Array` of `binaryString.length`, fill with `binaryString.charCodeAt(i)`, return `.buffer`
- NEVER use Node.js `Buffer` — D-14 requires browser-only APIs for mobile compatibility

**4. Network and vault integration functions:**

`fetchWithTimeout(url: string): Promise<{ buffer: ArrayBuffer; contentType: string }>` — per D-05, D-10:
- Create timeout promise: `new Promise<never>((_, reject) => setTimeout(() => reject(new Error('Download timeout: ' + url)), TIMEOUT_MS))`
- Create fetch promise: `requestUrl({ url, method: 'GET' })` then check `response.status !== 200` throw `Error('HTTP ' + response.status)`, then validate Content-Type via `isValidImageContentType(response.headers['content-type'])` — throw if invalid (D-08), then return `{ buffer: response.arrayBuffer, contentType: response.headers['content-type'] ?? '' }`
- Return `Promise.race([fetchPromise, timeoutPromise])`

`saveToVault(app: App, filename: string, notePath: string, buffer: ArrayBuffer): Promise<string>`:
- Call `app.fileManager.getAvailablePathForAttachment(filename, notePath)` — this handles DL-02 (vault attachment settings) and DL-03 (duplicate filename resolution) per D-04
- Normalize: `const normalized = normalizePath(attachPath);`
- Save: `await app.vault.createBinary(normalized, buffer);`
- Return `normalized`
- NEVER use `vault.adapter.writeBinary` — PITFALLS.md C3

`processOneRef(ref: ImageRef, app: App, notePath: string): Promise<DownloadResult>`:
- If `ref.type === 'base64'`:
  - Call `decodeBase64Image(ref.url)` to get buffer and mimeType
  - Check mobile size limit: `if (Platform.isMobile && buffer.byteLength > MOBILE_SIZE_LIMIT)` throw error (D-06)
  - Derive filename via `deriveFilenameFromBase64(mimeType)`
  - Save via `saveToVault(app, filename, notePath, buffer)`
  - Return `{ ref, localPath, status: 'ok' }`
- If `ref.type === 'http'` or `ref.type === 'wiki'`:
  - Call `fetchWithTimeout(ref.url)` to get buffer and contentType
  - Check mobile size limit on buffer (D-06): if `Platform.isMobile && buffer.byteLength > MOBILE_SIZE_LIMIT`, throw error
  - Also pre-check Content-Length header if available (this is already handled in fetchWithTimeout via Content-Type check; size check happens post-download on the buffer)
  - Derive filename via `deriveFilenameFromUrl(ref.url, contentType)`
  - Save via `saveToVault(app, filename, notePath, buffer)`
  - Return `{ ref, localPath, status: 'ok' }`

`downloadOneWithRetry(ref: ImageRef, app: App, notePath: string): Promise<DownloadResult>` — per D-09, ERR-01:
- Try `processOneRef(ref, app, notePath)`
- On first catch: if ref.type is 'base64', do NOT retry (no network involved), go straight to failure
- On first catch for http/wiki: retry once — try `processOneRef` again
- On second catch: `const error = e instanceof Error ? e.message : String(e);` (useUnknownInCatchVariables compliance), `console.warn('[download-image] Skipped ' + ref.url + ': ' + error)`, return `{ ref, localPath: '', status: 'failed', error }`

**5. Main exported function:**

`export async function downloadImages(refs: ImageRef[], app: App, notePath: string): Promise<DownloadResult[]>` — per D-11, D-12:
- If `refs.length === 0`, return `[]`
- Process in batches of `CONCURRENCY` (3): `for (let i = 0; i < refs.length; i += CONCURRENCY)`
- Each batch: `const batch = refs.slice(i, i + CONCURRENCY);`
- Use `Promise.allSettled(batch.map(ref => downloadOneWithRetry(ref, app, notePath)))` — allSettled ensures one rejection never blocks the batch (ERR-01)
- Collect results: fulfilled items push `.value`, rejected items (should not occur since downloadOneWithRetry always returns) push a failed DownloadResult as safety net
- Return all results

**TypeScript strictness compliance:**
- All catch blocks must narrow `unknown` type: `e instanceof Error ? e.message : String(e)`
- All optional chained access must handle undefined (noUncheckedIndexedAccess)
- All async functions must be awaited or have `.catch()` (ESLint obsidianmd)
- All parameters must be explicitly typed (noImplicitAny)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Plugin -> Remote server | Untrusted HTTP responses (status, headers, body) from arbitrary image URLs |
| Remote response -> Vault | Downloaded binary data written to user's vault filesystem |
| User document -> Parser | Document content contains URLs that become network targets |
| Base64 data URI -> Vault | Embedded data decoded and written as binary files |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | fetchWithTimeout | mitigate | Validate Content-Type starts with `image/` or is `application/octet-stream` before saving (D-08); reject `text/html` and other non-image types to prevent HTML injection into vault |
| T-02-02 | Tampering | fetchWithTimeout | mitigate | Check `response.status === 200` before accessing arrayBuffer (D-10); prevents processing error pages as images |
| T-02-03 | Denial of Service | fetchWithTimeout | mitigate | 30-second per-image timeout via Promise.race (D-05); 15MB mobile size limit (D-06); concurrency capped at 3 (D-11) |
| T-02-04 | Information Disclosure | downloadOneWithRetry | mitigate | Error messages logged to console.warn only (not exposed to Notice in Phase 2); URLs in error messages are the user's own document URLs, not secrets |
| T-02-05 | Elevation of Privilege | saveToVault | mitigate | Path resolution exclusively via `getAvailablePathForAttachment` (D-04) — no manual path construction, preventing directory traversal |
| T-02-06 | Spoofing | decodeBase64Image | accept | Base64 data comes from user's own document content; no external trust boundary. Malformed data URI throws and is caught by error isolation |
| T-02-07 | Denial of Service | decodeBase64Image | mitigate | Mobile size limit check on decoded buffer before vault write (D-06); prevents memory exhaustion from extremely large embedded base64 strings |
</threat_model>
