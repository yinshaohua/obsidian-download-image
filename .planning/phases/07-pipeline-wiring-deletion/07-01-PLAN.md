3. **Pre-deletion ENOENT guard (per D-07):**
   Only when `this.settings.cleanupMethod === 'trash'`:
   ```typescript
   if (this.settings.cleanupMethod === 'trash') {
       const trashFolder = this.app.vault.getAbstractFileByPath('.trash');
       if (!trashFolder) {
           await this.app.vault.createFolder('.trash');
       }
   }
   ```

4. **Progress Notice (per D-12, D-13):**
   ```typescript
   const progressNotice = new Notice('Cleaning up...', 0);
   ```

5. **Deletion loop (per D-05, D-06, D-08, D-09):**
   ```typescript
   let successCount = 0;
   let failCount = 0;
   for (const file of selected) {
       try {
           if (this.settings.cleanupMethod === 'trash') {
               await this.app.vault.trash(file, false);
           } else {
               await this.app.vault.delete(file);
           }
           successCount++;
       } catch (err) {
           failCount++;
           console.error(`[download-image] Failed to remove ${file.path}:`, err instanceof Error ? err.message : String(err));
       }
   }
   ```

6. **Hide progress, show result Notice (per D-10, D-11):**
   ```typescript
   progressNotice.hide();
   if (failCount === 0) {
       new Notice(`Cleaned ${successCount} attachments`);
   } else if (successCount > 0) {
       new Notice(`Cleaned ${successCount} attachments, ${failCount} failed (see console)`);
   } else {
       new Notice(`Cleanup failed: ${failCount} files could not be removed (see console)`);
   }
   ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user -> command palette | User triggers cleanup; no untrusted input crosses this boundary |
| scanner output -> modal | OrphanedFile[] from scanner displayed in modal; data is vault-internal |
| modal output -> deletion | TFile[] from modal confirmation used to call vault.trash/delete |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | vault.trash(file, true) | mitigate | Never pass `true` as second arg to vault.trash — per D-05, always use `vault.trash(file, false)` to avoid silent system-trash fallback on Windows/Android |
| T-07-02 | Denial of Service | .trash folder ENOENT | mitigate | Pre-create .trash via `vault.getAbstractFileByPath('.trash')` null check + `vault.createFolder('.trash')` before deletion loop (D-07) |
| T-07-03 | Denial of Service | single file deletion failure | mitigate | try-catch inside deletion loop — one file failure does not block remaining files (D-08). Failures logged to console with file path (D-11) |
| T-07-04 | Information Disclosure | error messages | accept | Only file paths and error messages logged to console; no secrets or PII in attachment paths. Low risk. |
| T-07-05 | Elevation of Privilege | permanent delete without consent | mitigate | Permanent delete requires explicit opt-in in settings (CLN-03, SET-01). Default is always 'trash' (recoverable). Modal confirmation required before any deletion (CLN-01). |
</threat_model>
